## 0. Summary

Five comparables were read. Two are the same design as the sprint: **`bibo242/blackboard-mcp`** (Node, MIT, npm 2026-09-10) is a stdio MCP over the *internal* `/learn/api/v1` with a session cookie, session-clock probe, typed errors and a read-only HTTP layer; it even reads the attempt detail (`studentSubmissionFiles`, `feedbackToUser`). **`python-kuleuven`** documents the same internal calls, including the four-hop file chain and a HEAD-follow to the signed URL that bb2dash already adopted. **`campus-cli`** is not public-v1-only: only its raw-API tool is; it also calls internal inbox routes. **`BlackboardSync`** lists Syracuse University with `blackboard.syracuse.edu` and reads the public API with a login-captured cookie.

Parity: of the thirteen calls, **six** have a public equivalent with the fields the stages read (memberships, course, teachers, categories, calendar; the grade-id step is obviated), **four** have one that lacks a stage-read field (announcements `isRead`, gradebook `submissionStatus`/`lastAttempt`, content `state`/file URLs, attempt files/receipt/feedback), **one** (attempt rows) is unverified for a student, **two** have none (schedule, assessment instructions). Only course and teachers are both same-field *and* read by a stage. The internal calls stay.

**Biggest risk:** the internal field names differ between comparables (`attemptReceipt.receiptId` vs `confirmationNumber`; nested vs flat `permanentUrl`), and two comparables' CDN allowlists would refuse SU's `*.content.blackboardcdn.com`.

## 1. Comparables

### 1.1 `alejooroncoy/campus-cli` (closest in features)

**Facts.** TypeScript, ISC (LICENSE:1), npm 2.2.1 on 2026-09-19 [registry]; 549 commits, 10 stars [page]. **30 tools**, not 27: 25 `blackboard_*`, 2 `banner_*`, 3 `uclass_*` (README:224-255). Host hard-wired to UPC (`CC api/client.ts:7-8`).
**Auth/session.** Playwright persistent profile `~/.blackboard-cli/browser-profile`, mode 0700, symlink refused (`CC auth/login.ts:13, 91-97`); waits for `JSESSIONID` or `BbRouter` on `/ultra` (login.ts:162); stores Blackboard-host cookies only, `session.json` mode 0600, temp file + rename (`CC auth/session.ts:12-32`). Expiry read from `BbRouter` `expires:` with a 24 h sanity cap, else 3 h (login.ts:12, 33-45); Entra `ESTSAUTHPERSISTENT` expiry kept as metadata (login.ts:65-80); XSRF from `BbRouter` `xsrf:` (login.ts:82-89), sent as `X-Blackboard-XSRF` when present (`client.ts:132`). Re-login: headless `silentRelogin` from the same profile (session.ts:93-113; login.ts:301-375). Detection is **401 only** → `SESSION_EXPIRED` (client.ts:173-182); a 302 or an HTML 200 is not handled.
**Endpoints.** Mostly public (`courses.ts:18, 43, 58`; v2 columns/attempts `assignments.ts:85, 208`), **but** the inbox uses internal `/learn/api/v1/messages/summary` and `/courses/{id}/conversations` (`courses.ts:172-216`). Only `blackboard_raw_api` is limited to `/learn/api/public/` (`client.ts:65-71`). Pagination follows `paging.nextPage` after a prefix check (`courses.ts:256-262`).
**Safety.** Central same-origin assert on every request (`client.ts:20-32, 159`); cookie/XSRF stripped on any cross-origin redirect (`client.ts:135-143`), added after a session-leak finding (CHANGELOG:74). Mutations carry `destructiveHint:true` and a fail-closed `elicitInput` form (`mcp-tools.ts:139-160, 822, 918, 1071`); **reads carry no annotations at all** (only the seven mutating/download tools do, lines 643-1071). Pacing: 4 concurrent API requests, files one at a time with a 350 ms gap (`api/pace.ts:21-25`); identical GETs coalesced, 20 s memory (`api/reuse.ts:25`). Downloads confined to one root, 100 MB/file (README:264).
**Tests.** `node:test` with hand-written stub clients, no recorded payloads (`tests/messages-api.test.ts:14-20`); security tests for origin/redirect rules (`tests/security.test.ts:24-45`).
**Borrow.** Central request choke point; `beforeRedirect` credential strip; `blackboardId` zod regex on every id (`mcp-tools.ts:~120`); elicitation shape; the pacing/coalescing design. **Avoid.** PostHog usage telemetry with a built-in key, opt-out via `POSTHOG_DISABLED=1` (README:467-486; the README also calls it "opcional", :386); 401-only expiry; the regex `/(?:^|\.)blackboard\.com$/` (`client.ts:12`) would reject `x.content.blackboardcdn.com` (inference from the pattern, not a tested failure).

### 1.2 `sanjacob/BlackboardSync` (+ its library `sanjacob/bblearn`)

**Facts.** Python 3.11, PyQt6, GPL-2.0 (pyproject:15); 79 stars, 708 commits, last commit 2026-06-16 [page]; PyPI `blackboardsync` 0.18.0, 2024-10-22 [registry]. **Syracuse University is a supported institution:** `UNIVERSITIES.md:151`; its `universities.json` entry has `api_url` and login `start_url` `https://blackboard.syracuse.edu`, target `/ultra/`, network `SYR-UNIV-NET` [code, `BS universities.json`]. That is a listing, not a test result (**O**).
**Auth.** A Qt web-view login on a persistent profile `BlackboardLogin`; every `cookieAdded` lands in an in-memory `RequestsCookieJar`; done when the page URL starts with the target (`BS qt/LoginWebView.py`, class body). No cookie is written to disk by the app: its config holds only university, folder, last-sync time, min year (`BS config.py:88-125`). Probe: `fetch_users('me')` (`BS sync.py:112-114`). Expiry: `BBUnauthorizedError` (401) → log out, user signs in again (sync.py:154-156). Cadence 30 min (sync.py:58); incremental by `modified >= last_downloaded` (`BS content/job.py`).
**Endpoints.** Public only, `{host}/learn/api/public/v{n}` (`BL api.py:54`), per-status exception classes (`BL exceptions.py:20-48`). `bblearn` wraps ~70 documented routes; useful as a **name-and-version index** (columns/attempts v2, courses v3, most others v1: api.py:399, 422, 446, 575).
**Tests.** pytest with a `strategies.py` [page]. **Read-only:** yes.
**Borrow.** SU is on the list, so the public API plausibly answers a cookie at SU; the `BBResourceType` list of `x-bb-*` handlers (`BL blackboard.py`). **Avoid.** Copying code (GPL-2); its 20 MB / no-video filter (`BS content/webdav.py:86-103`).

### 1.3 `breitburg/python-kuleuven` (documents the internal API)

**Facts.** Python 3.13, CLI + MCP (`pycli-mcp`) + library; **no licence file** at `main` (raw 404); 19 commits, last 2026-08-23 [page]. Same reverse-engineering method as bb2dash, on KU Leuven's Ultra.
**Auth.** Scripted SAML with credentials/TOTP from env; Ultra has a second, independent SP: without its own handshake `/learn/api/v1/*` answers **401** (`KL src/kuleuven/session.py:58-60`). Reuse: persisted jar, ping, "200 + JSON = valid, anything else = expired" (`KL docs/AUTH.md:389-397`). Lifetimes noted: `_shibsession` 48 h absolute (AUTH.md:355). Not portable to Entra+Duo; the MCP README suggests putting username and password in the server's `env` so Claude can refresh (README, "Claude Desktop"), which B-43 forbids.
**Endpoints.** Internal `/learn/api/v1` (`toledo.py:38`), with the crawler's own queries: memberships (DATA.md:374-379), teachers `roleBucket=TEACHING&membershipAvailable=true` (:732), `schedule?sort=location(desc)` (:727), `gradebook/grades?userId=…` (:757; `toledo.py:203-215`), `contents/ROOT/children?@view=Summary&expand=assignedGroups,selfEnrollmentGroups.group,gradebookCategory&includeInActivityTracking=true` (:424-429). Documents Ultra Documents (`isBbPage` folder + child titled `ultraDocumentBody`, :474-498), the INTERACTIVE root (:768-784), `utilities/timeUntilBbSessionInactive` (:795, 1103), and "stay below about 1 request per second per endpoint" (:1108-1111, no limit observed).
**MCP shape.** Tools mirror CLI verbs; **the two disk-writing commands are excluded** and a `files resolve` tool returns the signed URL instead (README, "kuleuven mcp start"); the library "is pure: HTTP in, Pydantic models out, no disk I/O" (README, "Python API").
**Tests.** pytest + `respx`, inline payload fixtures in `tests/conftest.py`; offline; not recorded traffic.
**Borrow.** `DATA.md` as a data dictionary to diff against `DATA_SYNTAX.md`; the pure-library / no-disk-writes-in-MCP split. **Avoid.** Credentials in MCP env.

### 1.4 `bibo242/blackboard-mcp` (upstream `felipedias-ie`) — the closest design

**Facts.** TypeScript, Node ≥22.5, MIT (`package.json`); npm 0.1.2, first published 2026-09-10 [registry]; 15 commits [page]. About 35 `bb_*` tools (README:174-237).
**Auth/session.** Imports `BbRouter` (plus the IdP's cookies) from the user's browser profile; `--paste` fallback from a cURL; Chrome 127+ on Windows blocks the import (App-Bound Encryption, README:95-100, claim by the README). State in `~/.blackboard-mcp/`, AES-256-GCM, key in the OS keychain or a 0600 file (README:294). Expiry: 401; 403 whose body says session/login; a redirect to a login path; HTML where JSON was expected (`FD client/http.ts:46-52, 259-283, 341-345`). Session clock: `timeUntilBbSessionInactive` in ms; `keepBbSessionActive`; keeper ticks every 10 min (`FD client/index.ts:134-200`, `endpoints.ts:31-33`). Silent renewal replays the SAML chain over HTTP with the IdP cookies (README:69-90). XSRF, `Origin`, `Referer` only on non-GET (`http.ts:210-215`). Concurrency 4, 120 ms minimum gap, `Retry-After` honoured (`http.ts:58-59, 294-299`).
**Endpoints.** Internal by design, ~70 templates, each overridable from a profile file, plus `har import` to correct them (`endpoints.ts:5-23`; README:277-289). Also `PUT utilities/batch` for up to 20 reads per request (endpoints.ts:35-36).
**Safety.** Non-GET refused unless `BLACKBOARD_MCP_ALLOW_WRITES=1` (`http.ts:196-199`); reads are `readOnlyHint:true, openWorldHint:true` (`tools/grades.ts:73`). Typed error codes with `hint` (`http.ts:278-300`).
**Tests.** `unit`, `protocol`, `auth`, `external` under `test/`; parsing-level (cookie input, XSRF, filenames, HTML→text, endpoint templates: `unit.test.ts:13-226`); no recorded traffic seen.
**Borrow.** Session-clock probe; the four-way expiry test; endpoint map as data; read-only refusal in the HTTP layer. **Avoid.** Reading Chrome's cookie store; its allowlist (`.blackboard.com`, `.bbcdn.io`, `.cloudfront.net`: `http.ts:118-127`) omits `blackboardcdn.com`.

### 1.5 Others

`nitsuah/bb-mcp` (TypeScript, MIT, commits to 2026-09-28 [page]): about 40 tools over the **public** API with an app key (OAuth2 client-credentials or PKCE; README:121-122, 188-194) — route A, unusable without registration; borrow only the per-tool email scrub (README:345). `peekwez/mcp-blackboard` and the other npm hits for "blackboard mcp" are shared-memory servers, unrelated [page, registry]. `Magnus2142/Blackboard-LMS-CLI` last released 2022-05-24 [registry]: stale.

## 3. Files from Node with the cookie

**Examples.** KL walks the chain with one GET and `follow_redirects=True`: `bbcswebdav` → 302 to `alt-<tenant>.blackboard.com` (one-time hashes) → 302 canonical path → 302 to `learn-<region>-…xythos.content.blackboardcdn.com` with an S3 signature, `X-Amz-Expires=21600` (six hours), bound to the session (`KL docs/DATA.md:649-672`); `resolve_signed_url` HEADs with redirects and returns the last URL so bytes need no cookie (`toledo.py:536-545`) — the pattern in `108_` §A.4. CC: axios follows redirects, credentials stripped off-origin (`client.ts:135-143`). FD: `redirect:'manual'`, cookies re-derived per hop, a login-path redirect is expiry (`http.ts:239, 256-273`); appends `xythos-download=true` to force bytes (`tools/files.ts:77`). BS: `requests` stream, 200 only, under the instance URL, under 20 MB, no video (`BS content/webdav.py:86-103`). The vendor's own doc: public `attachments/{id}/download` answers 302 with `Location: …/bbcswebdav/xid-…?token` [vendor `demo-code/accessing-content-attachments-with-cURL.md:452-478`, bearer token, not cookie].
**Pitfalls.** Sending the cookie cross-origin (CC's 1.4.1 leak, CHANGELOG:74); path traversal in server filenames (CC `client.ts:85-96`; FD unit tests); allowlists that omit `blackboardcdn.com` (CC `client.ts:12`, FD `http.ts:118-127`); a 401/403 on hop one meaning expiry (bb2dash: `session_expired`, §A.4).
**Maps.** bb2dash's `fetch_signed.mjs` design (manual hops, at most 3, final host `.content.blackboardcdn.com`) is stricter than all four. Hop count at SU is bb2dash's own (§A.4); the KL count of four is one more (an `alt-` host) and [U] for SU.
**Verdict.** No comparable does better; port `fetch_signed` to Node `fetch` with `redirect:'manual'` and keep the SU allowlist.

## 4. What the crawler reads that nobody else does

- **Attempts chain.** *Partly covered.* FD reads the same detail resource `gradebook/attempts/{attemptId}` (`endpoints.ts:81`), taking ids from the grade row's `lastAttemptId/firstAttemptId/highestAttemptId/lowestAttemptId` (`tools/grades.ts:242-246`), and reads `studentSubmission`, `feedbackToUser`, `attemptReceipt.confirmationNumber`, `studentSubmissionFiles` (grades.ts:249-290), downloading via the column-scoped `…/attempts/{id}/files/{fileId}/download` or `permanentUrl` (`tools/files.ts:520-540`). Two differences to test in the probe: the crawler's receipt key is `attemptReceipt.receiptId` and its file keys are nested `file.permanentUrl`/`file.fileName` (`bb_crawler.js:205-230`) whereas FD types are flat (`types.ts:299-307`). Neither KL nor CC has the crawler's `grades/{gradeId}/attempts` step (540), so that route stays bb2dash-only; FD's grade-row attempt ids may make steps 1–2 unnecessary.
- **`embedsDeep` over assessment instructions.** No comparable. CC/FD/KL extract `data-bbfile` from document bodies (`CC embedded-files.ts:95`; KL DATA.md:541-547) and CC reads `contentHandler.instructions` on the public item (mcp-tools.ts:722-724). bb2dash is the only source; the internal call stays.
- **`@view=Summary` children.** Covered twice (KL `toledo.py:321-335`; FD `client/index.ts:340-347`), identical expand list.
